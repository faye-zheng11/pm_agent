# Skill：阶段定位（Stage Gating）

> 共享地基。任何 agent 在产出或评审前，先跑这一步，判定产品当前处于哪个生命周期阶段，并领取该阶段的标准。**一处判断，全队复用**——同一个项目阶段，各 agent 各自换尺子。

## 什么时候使用

- independent-critic 评审前的第 0 步（决定用哪把尺子）。
- opportunity-researcher / product-shaper / user-experience-reviewer 产出前，确认当前阶段允许的动作。
- 任何"要不要更严格/更宽松"的判断之前。

## 前置读取

- `project.yaml`：`stage` 字段、active Bet、`pmf_rules`。
- `memory/evidence.md`、`memory/canon.md`：是否已有可重复的真实用户价值证据。
- 当前被评审/被产出对象本身。

## 判定逻辑（看"过没过门"，不看感觉）

按**客观门槛**判定，分界线是 PMF。**PMF 必须被挣得**——没有明确证据就不算过线，宁可判早一阶段。

| 判定 | 客观标志 |
|---|---|
| **① 探索期（0→1，~1.0）** | 还没有可证伪的 Bet；核心价值仍是假设 |
| **② 验证期（逼近 PMF）** | 已有至少一个可证伪 Bet，正在收集能证真/证伪的信号 |
| **③ 扩张/优化期（Post-PMF）** | 已按项目预先定义的判断规则确认可重复用户价值，并有可复算行为证据或稳定留存/付费/核心任务信号；单一问卷阈值不能独立证明 PMF。 |
| **④ 维护/迭代期** | 增长趋稳、核心不再大改、改动以维护与降本为主 |

**歧义时的默认**：无法确认是否已过 PMF → 默认判为**②验证期以下（Pre-PMF）**，不假设 PMF 已达成。

## 输出契约

```
阶段：①探索 / ②验证 / ③扩张 / ④维护
判定依据：（引用 project.yaml.stage + 具体证据/缺口）
本阶段标准：
  主问题：
  证据门槛：低 / 中 / 高
  "乱整"的定义：
  速度 vs 严谨：
置信：高 / 中 / 低（依据是否充分）
```

## 各阶段标准表（发给各 agent 的"尺子"）

| 阶段 | 主问题 | 证据门槛 | "乱整"= | 速度vs严谨 |
|---|---|---|---|---|
| ①探索 | 有没有人真的要 | 低（C级假设可，但要便宜可证伪） | 无 kill 条件就烧钱 / 不可逆大投入 | 速度 > 严谨 |
| ②验证 | 信号真吗、能重复吗 | 中（B级行为证据、可重复信号） | 把一次幸运当 PMF、不重复验证就扩张 | 开始严谨 |
| ③扩张 | 不破坏核心地放大 | 高（基线 / AB / 对照） | 拍脑袋改已验证核心、无对照、为改而改 | 严谨 > 速度 |
| ④维护 | 维持、降本、不退化 | 高 + 防回归 | 无谓大改、引入回归 | 稳定 > 变化 |

## 各 agent 如何消费本结果

| agent | ①探索 | ②验证 | ③扩张 | ④维护 |
|---|---|---|---|---|
| independent-critic | 逼 kill 条件，**别死卡证据** | 要求可重复信号 | 严查基线、防回归 | 拒无谓大改、防退化 |
| opportunity-researcher | 广撒网找机会 | 找能证真/证伪的信号 | 只找威胁核心的信号+竞品动向 | 监控异常 |
| product-shaper | 鼓励大胆假设+便宜验证 | 收窄到最该验的假设 | 护住已验证核心地优化 | 小步、可回滚 |
| user-experience-reviewer | 会不会有人爱 | 爱的是不是真的、卡点在哪 | 改动会不会赶走现有用户 | 别破坏用户习惯 |

## 边界

- 只判阶段与标准，不替 agent 做它本职的判断。
- 阶段跨越是重大事件（尤其过 PMF）：若证据显示"该升阶段但项目仍标旧 stage"，标记给 PM，不自行改 `project.yaml`。
