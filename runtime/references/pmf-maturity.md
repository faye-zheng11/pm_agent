# PMF 验证阶梯

> PMF 不是一个一次性通过的标签，而是一组逐步减少不确定性的学习阶段。
> 阶梯用于选择本轮验证目标，不是行业通用分数表。

## 五个阶段

1. `problem_signal`：确认具体人群在具体情境下确实有问题，并且已经用时间、金钱或替代方案应对。
2. `solution_validation`：确认提出的机制能让目标用户完成任务，而不是只喜欢概念或 Demo。
3. `repeat_value`：确认价值在新鲜感之后仍能带来重复使用、回访、留存或主动回到产品。
4. `business_model`：确认价值可以通过付费、续费、交易或其他可解释的商业行为成立。
5. `growth_readiness`：确认获取、激活、留存和口碑/渠道可以相对稳定地扩展，且不会靠投放掩盖产品价值不足。

## 使用规则

- 一个 Bet 只能有一个 `pmf_stage` 和一个 `primary_unknown`，本轮只解决一个最大未知。
- 前一阶段没有足够证据时，不跳到后一阶段。比如没有重复价值，不因为一次 Demo 反馈好就讨论规模化。
- “用户喜欢”“很火”“下载量增长”“单次转化”都不能单独证明 PMF。
- PMF 阶段与项目生命周期不同：项目可以处于验证期，但当前 Feature 仍可能只在验证问题信号。
- SaaS 指标、LTV/CAC、Rule of 40、40%“非常失望”调查等只能作为需核实的参考，必须说明品类、样本、用户资格和数据口径；不能写死为所有产品的放行线。

## 证据阶梯

按判断强度逐层组合，不要求每次都覆盖全部层级：

1. 用户行为：正在使用替代、迁移、自建解决方案、重复使用或付费。
2. 用户理解：目标用户能说清任务、价值和放弃成本；访谈仍需防止意愿冒充行为。
3. 产品行为：核心动作完成、再次回来、留存、复访或主动推荐。
4. 商业行为：付费、续费、采购、减少流失或可解释的单位经济性。
5. 增长行为：稳定获客、激活、留存与渠道，不依赖一次性种子或买量。

## 每轮实验必须回答

- 本轮验证哪个阶段和哪个最大未知？
- 什么观察结果会支持、收窄、转向或停止？
- 本轮明确没有验证什么？
- 实验结束后学到了什么，下一轮最值得验证什么？
