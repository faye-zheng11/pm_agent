# PM 工作台重构方案 v1

> 面向对象：idol101 及后续项目的 PM 主场工作台（`pm-workbench.html` + `cockpit_server.py`）
> 目标：从"agent 结果展示后台"升级为"PM 的项目主场"
> 状态：**待评审**（评审通过后再拆分实现）

---

## 0. 一句话结论

现在的三条不满（UI 死板 / 用起来不连贯 / 资料点进去只有一句话）不是三个 bug，而是同一个根因的三个切面：**工作台承载的是"agent 运行结果"，而不是"PM 的项目本身"**。因此方案不是"美化皮肤"，而是重排三层：**资料层、渲染层、信息架构层**。

## 2. 设计目标与原则

1. **意图路由，不让 PM 选工具**（核心）：PM 的活是杂的、流动的。"开工前先选哪个 agent"是反模式。工作台应按 PM 此刻的意图**自动路由到对应阶段**，agent 是隐形专家，不是菜单项。
2. **主线优先**：导航与首页围绕 PM 真实生命周期主线（找信号 → 塑形 → 走测评审 → 拍板 → PRD 交付 → 设计交付），新项目与老项目的新增/优化/迭代都走同一条线。
3. **资料可读，不是可点**：飞书 `.base`、Figma、飞书文档、GitHub、docx/pdf —— 目标是**在网页内直接看到内容**，不是给个跳转链接。
4. **结果有重点**：任何 agent/评审输出，先给 `TL;DR + 关键结论 + 证据`，长文默认折叠。
5. **连贯**：切换视图局部更新、不跳顶、有状态过渡；操作留在原地。
6. **在现有资产上升级**，不推倒：复用 token、后端结构与现有四个 agent，重点补"路由、渲染、资料接入、评审/设计交付"。

## 3. 目标信息架构（新）——主线模型

不再以"agent 菜单"组织，而是一条 PM 生命周期主线，agent 隐藏在阶段背后：

```
①找信号 ─▶ ②塑形 ─▶ ③走测评审 ⟲ ─▶ ④拍板 ─▶ ⑤PRD交付 ─▶ ⑥设计交付
opportunity  product   ux-reviewer      PM决策    delivery    design-delivery(新)
-researcher  -shaper    + critic
```

- **对老项目同样适用**：新增功能 / 优化 / 迭代，都是从某个阶段切入的同一条线。

**两个入口并存（都不含 agent 选择器）：**

- **说人话的入口**：一个输入框，PM 描述处境（"想在东南亚试试"/"这个功能想看用户买不买账"/"PRD 走起"）→ 系统判断落在 ①~⑥ 哪一步 → 直接进入并预填。
- **主线看板**：项目首页顶部即这条主线，每阶段显示状态（未开始/进行中/等你处理/已产出），可直接点任意阶段继续。

**侧栏（辅助，非主入口）：**
```
├── 项目主线 Flow        ← 首页：主线看板 + 说人话入口 + 产品完成度骨架
├── 资料 Materials       ← 资料中心（重做，见 §5）
├── 决策与证据 Memory     ← canon / assumptions / evidence / decisions
└── 产物 Artifacts       ← 生成物（含 PRD、demo、figma、概念图）
```

### 3.1 塑形阶段：产品完成度骨架

塑形不是一次问答，是 agent 陪 PM 把产品"从抽象长到齐全"。网页上用一个**完成度骨架**可视化（PM 比喻："手脚齐全、五官都有"）：

```
核心价值 ▓▓▓░  目标人群 ▓▓▓▓  功能设计 ▓▓░░  界面设计 ░░░░  交互设计 ░░░░
```

- 每格填满即该维度已定义；PM 一眼看到产品长齐没，而非读一堵文字。
- 收束交付：文字版 或 html 草稿 demo，PM 简单过目 → 进入 ③ 评审。

### 3.2 走测评审阶段：候选试用官 + 结构化报告

**目标**：弥补 PM 没时间做真调研/真测试，用 agent 结合网上/reddit 等公开信息，模拟真实用户走测。

- **人群由 agent 提议、PM 挑，不由 PM 从零配**：
  - 系统自动提议一组"试用官"卡片：头像 + 人物小传 + **来源标签（reddit 帖/评论/公开讨论）** + 契合度。
  - PM 只做加减：踢掉、"再抓一个不一样的"、或调维度（年龄/国家/岗位/粉丝性质/性别）—— 维度是筛选器，不是必填项。
  - 默认抓**目标人群 5 个画像**；高阶模式抓**非目标人群**画像（看外溢/新机会）。
- **两种视角 = 两种人设**：
  - `ux-reviewer`（用户评审）：真实用户画像，产出体感（卡点/爽点/原话吐槽）。
  - `critic`（独立评审）：资深产品/行业视角，产出专业问题（逻辑漏洞/留存陷阱/竞品盲区）。
- **报告结构化**：每个试用官 = 一张卡片（情绪分 / 卡点 / 一句原话 / 一条建议）；多 persona 汇总成一屏走测结论（共性问题排序 + 分歧点 + TL;DR）。
- **循环**：PM 看报告 → 决定采纳与否 → 采纳则回 ② 回炉重塑 → 直到 PM 拍板。

### 3.3 设计交付阶段（新 agent，放最后做）

拍板后，输入 PRD，产出三件套供前端开工：

1. 页面构成 / 要素 / 细节梳理。
2. **Figma 线框图**：写进 PM 自己的 Figma，附解释说明 + 组件状态变化。
3. 一组**提示词**给 gpt 生成界面概念效果图。

交付物 = `PRD + Figma 线框 + 概念图`。技术依赖：已接入的 Figma 官方 MCP 连接器（`use_figma` / `generate_figma_design`）。

## 4. 分期计划（按 ROI）

### P0 · 资料中心（最高价值，直接解决 ③④）

**目标**：桌面 `Oppaya/` 这批 idol101 资料真正归档进来，且网页内可读。

- **归档整理**：把桌面 10 份版本文档 + 3 份 `.base` + 2 份问卷 + AI 报告，规整进 `projects/idol101/`，统一命名与版本标签，写进 `imports/index.json`。
- **`.base` 解析器**（新）：`.base` = 飞书多维表格导出（gzip JSON，字段 `gzipSnapshot`）。解压 → 解析成表（表名/字段/行）→ 前端表格化展示、可搜索可筛选。覆盖 `角色书 / 平行时空剧本 / 捏人素材库 / 内测问卷`。
- **docx/pdf 预览**：docx → 文本+结构提取（python-docx / mammoth 转 HTML）；pdf → 已能按页读，做成分页预览。取消"binary 不展开"。
- **后端**：`material_detail()` 扩展 `format`：新增 `base_table` / `docx` / `pdf_pages`。
- **前端**：`renderMaterial()` 增加对应渲染分支；资料列表改为**分类 + 卡片**（缩略/类型/版本/更新时间）。

**动到的文件**：`cockpit_server.py`（material_detail、import）、`pm-workbench.html`（renderMaterial、材料列表）、新增 `scripts/base_parser.py`。

### P1 · 外部源内嵌预览（解决 ③ 的外链部分）

**目标**：飞书文档 / Figma / GitHub 链接——网页内看到内容，不是跳转。

- **飞书文档/表格**：走飞书开放平台 API（需应用凭证 + 授权），抓正文/表格渲染进来；未授权时降级为富预览卡片。
- **Figma**：Figma REST API 出缩略图/节点图（已有 Figma MCP 连接器可复用），内嵌图片预览 + 打开源文件。
- **GitHub**：README/指定文件正文抓取渲染，仓库元信息（star/最近提交）做成卡片。
- **连接器与登录**：统一在"外部源"里管理凭证状态（已连/未连/过期），未连时明确提示怎么连，而不是一句"取决于连接器"。

**依赖**：飞书/Figma/GitHub 的 token 或 OAuth。**需你确认可提供哪些凭证**（决定这期能做到"抓正文"还是只能"富卡片"）。

### P2 · 结果结构化 + 连贯交互（解决 ②）

- **结果结构化渲染**：agent 输出统一结构 `TL;DR / 关键结论 / 证据 / 展开详情`；升级 `simpleMarkdown()` 支持表格、加粗、代码、折叠；超长自动摘要 + 折叠。
- **局部更新路由**：切页只换主区、不跳顶、保留滚动位置；加入过渡动画与骨架屏（skeleton）。

### P3 · UI 语言升级（解决 ①）

- 在现有 token 上重建**层级系统**：hero 主区、卡片分级、留白节奏、字号阶梯（不再全 13px）。
- 空态、加载态、成功/否决态都有视觉表达。
- 首页改为"项目叙事"版式：`当前在赌什么` 为最大主区，其下挂 `支撑证据 / 待验证假设 / 建议下一步`。

## 5. 资料中心技术方案（P0 细化，核心）

### 5.1 `.base` 文件解析

- 格式：单行 JSON，`{"gzipSnapshot": "<base64 of gzip>"}`。
- 步骤：base64 decode → gzip 解压 → JSON.parse → 提取 `tables[].records[]` → 归一化成 `{表名, 列定义, 行数据}`。
- 展示：每张表一个可折叠面板；表格支持列筛选、关键词搜索；长文本单元格点击展开。
- 落地：`scripts/base_parser.py`（纯 Python，标准库 gzip/base64/json，无新依赖）。

### 5.2 版本文档（docx/pdf）

- docx：优先 `mammoth`（转 HTML，保留标题/列表/表格）；无依赖时降级为 `python-docx` 纯文本 + 结构。
- pdf：沿用现有按页读取，前端做分页器 + 页内文本；大图页可选渲染缩略。

### 5.3 归档结构（建议）

```
projects/idol101/materials/
├── versions/        V1.0.0.docx … V3.4.0.pdf（原件）
├── data/            角色书.base / 平行时空剧本.base / 捏人素材库.base
├── research/        内测问卷.base / 第二次内测-AI报告.pdf
└── ui/              UI 截图目录（可选）
imports/index.json   ← 全部登记，带 kind / version / updated_at
```

> 注意：桌面 `Oppaya/` 是**一手原件**，归档采取"拷贝进项目 + 登记"，不删除桌面原件，避免误删。
