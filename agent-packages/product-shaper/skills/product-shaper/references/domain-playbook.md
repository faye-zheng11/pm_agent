# 想法收敛知识包（Shaping Playbook）

> product-shaper 的自有知识资产（**Asset，不是 agent**）。收敛前先读它。
> **A 预装**（公认、开箱即用）+ **B 沉淀**（真实收敛长出来）。信任红线：品类规律可引用；具体竞品事实必须带来源，否则标"未核验"。

---

## A. 预装 playbook

### A1. 好问题框架长什么样（证据级 A：公认）

| 强框架 | 弱框架 |
|---|---|
| 谁在什么情境下、卡在什么事上 | "用户想要 X 功能" |
| 用户已用 workaround/别处付费解决 | "要是有 X 就好了" |
| 成功信号是可观察行为 | 成功信号是"更满意" |
| 目标用户能找到具体的人 | "所有 K-pop 粉丝" |

### A2. 可证伪赌注怎么立（配 pmf-bet-brief）
一个能造的赌必须能回答：**赌什么用户会做什么行为 · 怎么算错(kill) · 多久看 · 先找哪 5 个真实用户**。三缺一 → shaping-kill。

### A3. 品类价值规律：AI 陪伴 / K-pop 关系产品（证据级 B）
- 强价值锚点：**可积累的关系**（历史、养成、回访结构）> 一次性互动。
- 弱信号要打折：情感"好想要"极易说、极难转成留存/付费；优先找已投入行为。
- 功能级红线：别用新功能**稀释核心关系感**；别把情感触点粗暴货币化。

### A4. shaping-kill 判据清单（想法立不起来的信号）
- 目标用户写不到"能去哪找到 5 个人"。
- 只有功能愿望，没有"已在别处花钱/花时间解决"的证据。
- 说不清 kill 条件与观察窗。
- （功能级）和已验证核心无关，或会伤现有用户习惯。

### A5. 两高度收敛差异
| | 项目级 | 功能级 |
|---|---|---|
| 收敛成 | 新方向可证伪判断 + go/no-go | Feature/升级规划 |
| 必查 | 有没有真实可及的困境 | 契合核心 + 不伤现有用户 + 竞品差距 |
