# 模拟用户体验评审知识包

## 稳定检查项

- 用户进入后能否在十秒内知道产品是什么、为什么与自己有关。
- 首次价值是否在要求注册、付费或提供敏感信息之前出现。
- 产品是否把重复任务包装成关系、成长或陪伴，却没有真实变化。
- 用户拒绝、退出、降级和删除数据是否足够清楚。
- 文化、角色、身份和情绪表达是否容易造成冒犯或失真。
- 视觉层级、状态反馈、错误恢复和无障碍是否支持关键任务。

## 常见误判

- 把 PM 的理解能力当成新用户理解能力。
- 把高参与用户的耐心投射给普通用户。
- 把概念新鲜感当成复访动机。
- 把 Synthetic Persona 的顺从回答当成真实接受度。
- 只审顺利路径，不审拒绝、退出、失败和恢复。

## 使用规则

结合项目目标用户和真实 Evidence 使用；具体用户反应若没有来源，只能写成待验证假设。

## 可切换的 Synthetic 用户群体

`persona_review` 可以按项目选择不同群体，不能把群体库当作真实用户样本：

- 唯粉：重视单一成员的专属感，警惕角色失真和关系越界。
- 团粉：关注群体内容、成员协作和信息完整性，不接受只为单一成员设计的默认路径。
- 妈粉：关注守护感与安全边界，警惕恋爱化、情绪操控和付费套路。
- 事业粉：关注内容价值、活动效率和对艺人事业的实际帮助。
- CP 粉：关注关系动态、共同事件和双人叙事，单人陪伴可能不成立。
- 颜粉：首先判断视觉质感、内容呈现和第一眼吸引力。
- teen：时间碎片、预算有限，对隐私、付费和情绪影响更敏感。
- 海外粉：关注语言、时区、文化语境和非中文用户是否被排除。

模拟反应必须写成 `synthetic_assumption`，每条重要风险都要转换为真人研究问题，不能输出虚构引语或“用户一定会喜欢”。
